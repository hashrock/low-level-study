# minicc — minilang を RISC-V 64 ネイティブコードにするコンパイラ

隣の `../lang` (minilang: 字句解析 → Pratt パーサ → AST → **バイトコード VM**) と同じ言語を、
**RV64IM のアセンブリ** に直接コンパイルします。出力した `.s` は `../asm` でランタイム
(`runtime/runtime.s`) と一緒にアセンブル・リンクされ、`../emu` で Linux 静的 ELF として動きます。
学習目的は「スタックフレーム・呼び出し規約・レジスタ・ランタイム支援」をネイティブコード生成で体験し、
バイトコード VM と比べることです。Go 標準ライブラリのみ。

```sh
go run . emit  examples/fib.lang              # アセンブリを表示
go run . build examples/fib.lang -o fib       # fib.s を出力し ../asm で fib (ELF) を作る
go run . run   examples/fib.lang              # build して ../emu で実行
go vet ./... && go test ./...                 # examples を コンパイル→アセンブル→エミュレータ実行 して比較
go test -run TestExamples -update .           # examples/*.out を作り直す
```

## ファイル構成

| ファイル | 行数 | 役割 |
|---|---:|---|
| `lexer.go` `parser.go` `ast.go` | 570 | `../lang` から**そのままコピー** (先頭にコピー元を記載) |
| `resolve.go` | 282 | 名前解決と捕捉解析: 各変数がグローバル / スロット / 箱 のどれに住むかを決める |
| `codegen.go` | 642 | AST → アセンブリ。フレーム配置、式、制御構文、呼び出し、クロージャ生成 |
| `main.go` | 110 | CLI (`emit` / `build` / `run`)、`../asm` `../emu` の起動 |
| `runtime/runtime.s` | 1531 | ランタイム (RISC-V アセンブリ): 割り当て、表示、文字列、配列、マップ、型検査、エラー |
| `minicc_test.go` | 155 | examples の照合、`../lang` インタプリタとの照合、エラーのテスト |

### パーサをコピーした理由

`../lang` は `package main` なので Go の仕組み上 import できません (`replace` ディレクティブを使っても
main パッケージは import 不可)。`../lang` 側は変更しない約束なので、`lexer.go` `parser.go` `ast.go` の
3 ファイルを変更せずにコピーしました。どちらの処理系も同じ AST を読むので、
「フロントエンドは共通で、バックエンドだけ違う」という比較がしやすくなります。

`runtime.s` を `runtime/` に置いているのは、Go のツールは パッケージディレクトリ内の `.s` を
**Go アセンブラ** のファイルとみなし、`go vet` / `go build` が失敗するためです。

## 対応している言語機能

`../lang/examples` の 6 本 (fib, fizzbuzz, closures, higher_order, maps, no_coercion) はすべて
インタプリタと**同じ出力**になります (`TestAgainstInterpreter`)。

- 値: 整数、文字列、`true`/`false`、`nil`、配列、マップ (挿入順)、関数 (クロージャ)
- `let` / `const` (再代入はコンパイルエラー)、ブロックスコープ、未宣言変数はコンパイルエラー
- `+ - * / %`、`== != < <= > >=` (文字列は辞書順)、`&& || !` (短絡評価で値そのものを返す)、`= += -= *= /=`
- `if/else`、`while`、`for (x in 配列/マップ)`、`break`/`continue`/`return`
- 関数宣言・無名関数・`=>`、再帰、相互再帰 (トップレベル)、局所関数の自己再帰
- クロージャ (捕捉変数はヒープの箱。ループ変数は反復ごとに新しい箱)
- 組み込み関数: `print len push pop keys has type str range` (値として渡すこともできる: `type(print)`)
- 実行時の型検査 (暗黙の型変換なし)。エラーは `行:列: runtime error: ...` を stderr に出して `exit(1)`

## 値の表現: 下位ビットでタグ付けした 64bit 1 語

RV64IM には浮動小数点命令 (F/D 拡張) がなく、`../asm` と `../emu` も対応していないので、
**数値は整数のみ** としました (本家との違い。下記「制限」)。すべての値を 64bit レジスタ 1 本に収めます。

```
 63                                    3 2 1 0
+---------------------------------------+-----+
|            n (63bit 符号付き)           |...1 |   整数 n は 2n+1 (最下位ビット 1)
+---------------------------------------+-----+
|                                  0b010 = 2    |   nil
|                                  0b100 = 4    |   false
|                                  0b110 = 6    |   true
+---------------------------------------+-----+
|     ヒープ object のアドレス             | 000 |   ポインタ (8 バイト境界なので下位 3bit が 0)
+---------------------------------------+-----+
```

なぜこの表現か:

- **整数演算がタグを外さずにできる**: `(2a+1) + (2b+1) - 1 = 2(a+b)+1`。`add` + `addi` の 2 命令。
  大小比較はタグ付きのまま `slt` で正しい (2n+1 は単調増加)。
- **型検査が安い**: 「両方整数か?」は `and t0, a0, a1; andi t0, t0, 1` の 2 命令。
  整数でなければランタイム (`rt_add` など) に任せ、そこで文字列連結か型エラーかを判断します。
- 真偽判定は「`false` と `nil` だけが偽」なので、2 回の比較で済みます。
- 全部をヒープの箱に入れる (boxing) と、`n - 1` のたびに割り当てが起きて遅く、GC が必須になります。

ヒープ object は先頭の 1 語が型タグです:

```
文字列    [1][長さ][バイト列...]                  リテラルは .rodata に静的に置く
配列      [2][長さ][容量][要素バッファ*]           push で容量を倍々に作り直す
マップ    [3][キー配列*][値配列*]                  挿入順を保つ。線形探索
関数      [4][コード*][引数の数][名前*][捕捉数][箱*][箱*]...
組込関数  [5][コード*][引数の数][名前*][0]          runtime.s に静的に置く
箱        [値]                                    捕捉された変数 1 個
```

メモリは `.bss` の 64 MiB 領域からのバンプ割り当てで、**解放しません (GC なし)**。

## スタックフレーム

関数に入ったときの `sp` を `fp` (= `s0`) に保存し、すべてのスロットを `fp` からの負のオフセットで
指します。式の途中結果も、`sp` を動かす push/pop ではなく **深さごとに決まった一時スロット** に置くので、
`sp` は関数の中で一度も動きません (16 バイト境界は prologue で揃えるだけで保たれる)。

```
        高位アドレス
        |  呼び出し元のフレーム     |
fp ───▶ +--------------------------+  ← 呼び出し時の sp
 -8     | ra (戻りアドレス)          |
 -16    | 呼び出し元の fp            |
 -24    | 自分のクロージャ (環境)     |   捕捉変数はここから辿る
 -32    | スロット 0  (引数 1)       |
 -40    | スロット 1  (ローカル変数)  |   捕捉される変数なら「箱へのポインタ」
  ...   | for-in の隠しスロット      |   (反復対象の配列, 添字)
        | 一時スロット 0             |   二項演算の左辺、呼び出しの引数など
        | 一時スロット 1 ...         |
sp ───▶ +--------------------------+  (16 バイト境界)
        低位アドレス
```

フレームの大きさは関数本体を生成し終えてから (一時スロットの最大深さが分かってから) 決まるので、
本体を先にバッファに出し、後から prologue を前に付けています。

```asm
fn_1_fib:
	addi sp, sp, -64          # prologue: フレームを確保
	sd ra, 56(sp)
	sd fp, 48(sp)
	addi fp, sp, 64
	la t0, rt_stack_limit     # Go と同じく、入口でスタックの残りを確認
	ld t0, 0(t0)
	bgeu sp, t0, .Lstack_ok_24
	call rt_stack_overflow
.Lstack_ok_24:
	...
.Lret_5:                      # epilogue (return はここへ j する)
	ld ra, 56(sp)
	ld fp, 48(sp)
	addi sp, sp, 64
	ret
```

## 呼び出し規約

RISC-V psABI の整数規約に合わせ、**隠し第 0 引数としてクロージャ** を渡します。

| レジスタ | ユーザ関数 | ランタイム `rt_*` |
|---|---|---|
| `a0` | 呼ばれるクロージャ (自分の環境) / 戻り値 | 第 1 引数 / 戻り値 |
| `a1`–`a7` | 引数 1〜7 (8 個以上は未対応) | 第 2 引数〜 |
| `ra` | 戻りアドレス (`jalr` が書く) | 同じ |
| `s0` (`fp`) | フレームポインタ (callee-saved) | 保存する |
| `s1`–`s11` | 使わない | 使うなら保存する |
| `t0`–`t6` | 壊してよい | 壊してよい |

生成コードは値をすべてフレームに置くので、呼び出しをまたいで生きるレジスタがありません。
そのため caller-saved / callee-saved を気にする必要があるのは `ra` と `fp` だけです。

呼び出し `f(x)` の手順:

```asm
	ld a0, -40(fp)            # 一時スロットに置いておいた f
	li a1, 1                  # 引数の数
	call rt_checkcall         # 関数か? 引数の数は合うか? (違えば実行時エラー)
.Lsite_14:
	ld a1, -48(fp)            # 引数 1
	ld t0, 8(a0)              # クロージャの 2 語目 = コードのアドレス
	jalr t0                   # 間接呼び出し
.Lsite_15:
```

### 実行時エラーの位置: 戻り番地 → ソース位置の表

失敗しうるランタイム関数は、入口で自分の `ra` を `rt_site` に記録します。コンパイラは各 `call` の直後に
ラベルを置き、`mini_sites` という表 (`戻り番地, 行, 列`) を `.rodata` に出力します。エラー時には
ランタイムが `rt_site` を表で引いて `20:11: runtime error: ...` と表示します。
デバッガが PC から行番号を引く (DWARF の line table) のと同じ考え方で、通常時のコストはゼロです。

### クロージャ: `fn adder(n) => fn(x) => x + n`

`n` は内側の関数から参照されるので、捕捉解析 (`resolve.go`) が「箱に入れる」と決めます。

```asm
fn_1_adder:                       # adder(n)
	...
	sd a1, -32(fp)               # 引数 n
	ld a0, -32(fp)
	call rt_box                  # n は捕捉されるので箱に入れる
	sd a0, -32(fp)               # スロットには箱へのポインタ
	li a0, 1                     # 捕捉数
	la a1, fn_2                  # コード
	li a2, 1                     # 引数の数
	la a3, .Lstr_1               # 名前 "<anon>"
	call rt_closure_new
	ld t0, -32(fp)               # n の箱
	sd t0, 40(a0)                # クロージャに箱ポインタをコピー (値ではなく箱を共有)
	j .Lret_6

fn_2:                             # fn(x) => x + n
	...
	ld t1, -24(fp)               # 環境 (自分のクロージャ)
	ld a0, 40(t1)                # 捕捉した n の箱
	ld a0, 0(a0)                 # 箱の中身
```

- 捕捉されない変数は箱を作らず、スロットへの `ld`/`sd` 1 回でアクセスします。
- 何も捕捉しない関数 (トップレベルの `fib` など) のクロージャは `.data` に静的に置き、割り当てません。
- 孫関数が祖父の変数を使う場合、間の関数も箱を受け取って中継します (`examples/nested_closures.lang`)。
- `let` / for-in の変数は実行のたびに新しい箱を作るので、ループ内のクロージャは反復ごとに別の値を捕捉します。

## バイトコード VM (`../lang`) との比較

| | バイトコード VM | minicc (ネイティブ) |
|---|---|---|
| 実行するもの | 自作の命令列を Go の `switch` でディスパッチ | CPU (エミュレータ) が直接実行する機械語 |
| 値 | Go の `any` (型情報は Go が持つ) | タグ付き 64bit 語。型はビットとヘッダで自前管理 |
| オペランドの置き場 | VM の値スタック | レジスタ `a0`/`a1` + フレーム内の一時スロット |
| ローカル変数 | 全部セル (`*Cell`) に入れる | 捕捉されるものだけ箱。それ以外はフレームのスロット |
| 関数呼び出し | `CALL n`: Go の配列にフレームを積む | `jalr`。`ra`/`fp` の保存、prologue/epilogue を自分で書く |
| 型検査・演算 | `ADD` 命令の中で毎回型を switch | 整数の速い道をインライン、それ以外はランタイム呼び出し |
| エラー位置 | 命令ごとの位置表を VM が引く | 戻り番地 → 位置の表をランタイムが引く |
| メモリ管理 | Go の GC | バンプ割り当てのみ (解放しない) |
| 組み込み関数 | Go の関数 | RISC-V アセンブリ (`runtime.s`) |

参考までに、`examples/fib.lang` (fib(0..14), fibLoop(50), fib(25)) は約 1700 万命令で動きます
(`cd ../emu && go run . run --stats prog`)。

## 制限 (本家 minilang との違い)

- **数値は 63bit 整数のみ**。小数リテラルはコンパイルエラー、`/` は 0 方向に切り捨て (`7 / 2` → `3`)。
  オーバーフローは検出しません (本家は float64 なので `2^53` を超えると表示が `1.15e+18` 形式になる)。
- GC なし: 64 MiB のヒープを使い切ると `out of memory`。
- 関数の引数は 7 個まで (`a1`–`a7` に収まる分)。フレームは 2 KiB まで (`sd` の 12bit オフセット)。
- 文字列はバイト列として扱う (`len` と添字は UTF-8 のバイト単位。本家は rune 単位)。
- 組み込み関数を値として使うと引数の個数が固定 (`print` は 1 個、`range` は 1 個)。
  組み込みを直接呼ぶ場合の引数の個数違いはコンパイルエラー (本家は実行時エラー)。
- 実行時エラーにスタックトレースは付きません (位置 1 つだけ)。スタックオーバーフローは位置なし。
- トップレベルで、後で宣言されるグローバルを参照するとコンパイルエラー (本家は実行時エラー)。
  関数の中からは後で宣言されるグローバルも参照できます (相互再帰のため)。
- マップは線形探索、print の 1 行は 1 MiB まで、REPL はありません。
- 最適化はしていません (レジスタ割り当てなし、すべての値がフレームを経由する)。
