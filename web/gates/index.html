1.トランジスタ → ゲート (CMOS)

  

    

      
CMOS NOT (インバータ)

      

      

    

    

      
CMOS NAND

      

      

    

    

      
pMOS はゲートが 0 のとき、nMOS はゲートが 1 のときにスイッチが閉じます (導通)。
        CMOS では上 (VDD 側) に pMOS、下 (GND 側) に nMOS を置き、必ずどちらか一方だけが出力につながるので、
        出力は 1 (≈1V) か 0 (0V) のどちらかにはっきり決まり、定常状態ではほとんど電流が流れません。
        NAND は pMOS 2 個を並列、nMOS 2 個を直列につないだもので、A と B が両方 1 のときだけ GND への道ができて出力が 0 になります。

      
NAND だけで全部作れる: NOT A = NAND(A, A)、AND = NOT(NAND)、OR = NAND(NOT A, NOT B) (ド・モルガンの法則)。
        AND と OR と NOT が作れれば、どんな真理値表でも作れるので、NAND (または NOR) 1 種類で
        CPU 全体が組み立てられます。実際のチップでも NAND/NOR 系のセルが基本部品です。下は NAND 3 個で作った OR です。

      

        

        

      

      
試してみよう
        
    
          
  • NOT の A を切り替えて、pMOS と nMOS が 交互に 導通することを確かめる。
    • 
          
  • NAND で A=1, B=1 のときだけ、nMOS 2 個が両方つながって出力が GND (0V) に落ちるのを見る。
    • 
          
  • NAND で A=1, B=0 のとき、nMOS の間の節点 (X) が「どこにもつながっていない (浮いている)」状態になるのを見る。
    • 
          
  • NAND 3 個の回路の真理値表が OR と同じになるか確かめる。

3.半加算器 → 全加算器 → 4 ビット リップルキャリー加算器

  

    

      
半加算器 (half adder)

      

      
1 ビット同士の足し算。S (和) = A XOR B、C (桁上げ) = A AND B。1 + 1 = 102 なので S=0, C=1。
        ただし下の桁からの桁上げを受け取れないので、2 ビット目以降には使えません。

    

    

      
全加算器 (full adder)

      

      

      

    

    

      
4 ビット リップルキャリー加算器

      

        
        
        
        
        
        
        
      

      

        

        

          

          

          

          
2 の補数と符号拡張

          
4 ビットで負の数を表すとき、1111 を −1、1000 を −8 とみなします
            (最上位ビットの重みを +8 ではなく −8 にする)。これが 2 の補数。−x は「全ビット反転して +1」で作れます
            (0001 → 1110 → 1111 = −1)。うれしいのは、符号付きでも符号なしでも、同じ加算器がそのまま使える こと。
            5 + 15 = 20 = 1_01002 の下位 4 ビットは 0100 = 4 で、これは 5 + (−1) = 4 そのものです (あふれた Cout は捨てる)。

          
符号拡張: 4 ビットの −1 (1111) を 8 ビットにするときは、最上位ビット (符号) をコピーして
            1111_1111 にします (0 で埋めると 15 になってしまう)。今の B を 8 ビットに符号拡張すると
            。
            hw の即値生成器 immgen.v の {{52{s}}, inst[31:20]} がまさにこれで、
            addi a0, a0, -1 (= 0xfff50513) の 12 ビット即値 0xfff が
            64 ビットの 0xffff_ffff_ffff_ffff (= −1) になり、ALU が 5 + 0xffff…ffff = 4 (桁あふれ) を計算します。

          
→ hw/README「波形を読む: addi a0, a0, -1」、
            immgen.v、
            alu.v の `ALU_ADD: r = a + b;

        

      

      
クリティカルパスとクロック周期

      
ゲートは入力が変わってから出力が変わるまで少し時間 (ゲート遅延) がかかります。このページでは全ゲートの遅延を 1 としています。
        ビット i の桁上げ ci+1 は ci が決まるまで決まらないので、桁上げが下の桁から順に 波のように (ripple) 伝わります。
        最も長い経路 (クリティカルパス) は A0 → p0 → t0 → c1 → t1 → c2 → … → c4 で、n ビットなら 2n + 1 ゲート遅延
        (4 ビットで 9)。途中の S は一瞬まちがった値になり (グリッチ)、最後に落ち着きます。

      
CPU はこの「落ち着くまで」をクロックの立ち上がりまでに終わらせる必要があります。
        hw/README のデータパス にある通り、単一サイクル CPU では
        「pc → 命令 RAM → デコーダ → レジスタ → ALU → データ RAM → 書き戻し」の全部が 1 クロックの中に入るので、最長経路がクロック周期を決めます。
        たとえば 1 ゲート 20 ps とすると、64 ビットのリップルキャリー加算器だけで 129 × 20 ps ≈ 2.6 ns (≈ 390 MHz が上限)。
        実際の CPU は桁上げを先読みする加算器 (carry-lookahead など) で経路を log n 程度に縮め、さらに
        パイプライン で 1 クロックの仕事を短く切ってクロックを上げます。

      
試してみよう
        
    
          
  • 「5 + (−1)」を押す。B = 1111 で、桁上げが bit0 から bit3 まで順に 1 になり、S = 0100 = 4、Cout = 1 になる (Cout は捨てる)。
    • 
          
  • 「最長経路」を押して、安定までの時間が 9 ゲート遅延になることを確認。アニメーションを「ゆっくり」にすると桁上げの波が見えます。
    • 
          
  • S3 が一度 1 になってから 0 に戻る (グリッチ) のを探す。クロックの立ち上がりまでに落ち着けば問題ありません。
    • 
          
  • 「7 + 1」: 符号なしでは 8 で正しいが、符号付きでは +7 + 1 = −8 になる (符号付きオーバーフロー)。
    • 
          
  • 左の Cin を 1 にすると A + B + 1。B を全ビット反転して Cin = 1 にすれば A − B になります (alu.v の a - b の作り方)。

4.マルチプレクサ (どちらかを選ぶ回路)

  

    

      
2:1 マルチプレクサ

      

      
y = s ? b : a。s = 0 なら上の AND だけが開いて a が通り、s = 1 なら下の AND が開いて b が通ります。
        Verilog の ? : (条件演算子) や case は、合成するとこの回路になります。

      

    

    

      
4 ビット 2:1 マルチプレクサ = ALU の入力 B (b_sel)

      

        
        
      

      

      

      
2:1 マルチプレクサをビットの数だけ並べ、選択線 b_sel を全部に配ったものです。
        hw のコアでは alu_b = (b_sel == `B_IMM) ? imm : rs2_val; (64 ビット)。
        デコーダが命令を見て b_sel を決めます: add なら レジスタ rs2、addi/lw/sw なら即値。

      
→ core.v の alu_b、
        hw/README「制御信号の表」、
        CPU データパスのページ

    

    

      
試してみよう
        
    
          
  • 2:1 マルチプレクサで s を切り替え、選ばれていない側の入力をいくら変えても y が変わらないことを確かめる。
    • 
          
  • 「addi」を押すと b_sel = 1 で即値 1111 (−1 の下位 4 ビット) が ALU に入り、「add」では rs2 (a1) の値が入る。
    • 
          
  • s を変えたとき、NOT を通る分だけ上の AND が遅れて変わり、y が一瞬 0 になる (グリッチ) ことがある。アニメーションをゆっくりにして探そう。

5.命令デコーダ (opcode → 制御信号)

  

    

      

      

      

    

    

    

      
opcode の一致検出 (AND 平面)

      

      
上のスイッチが inst[6:0] (opcode)。各ビットとその反転 (NOT) を縦に走らせ、
        横の行が 7 入力 AND です。丸い接点が「その行が見るビット」で、opcode が 1 の桁は元の線、0 の桁は反転した線につないであります。
        7 個の接点が全部 1 のときだけ、その行の出力が 1 になります。例えば is_load は
        ~i6 & ~i5 & ~i4 & ~i3 & ~i2 & i1 & i0 (= 0000011)。

    

    

      
制御信号 (OR 平面)

      

      
* ecall (system) の reg_we は命令語全体が 0x00000073 のときだけ (ここでは省略)。
        load/store の funct3 による illegal も省略しています。

      
decoder.v の対応する行

      

      
→ decoder.v、
        defs.vh の OPC_*、
        制御信号の表、
        用語集「opcode / funct3 / funct7」「命令形式」

    

    

    

      
decoder.v は case (opcode) と always @(*) で書かれていますが、合成ツールはこれを
        「opcode を比べる AND の行」+「どの行で 1 にするかを集める OR」という 2 段の論理に直します。
        always @(*) の先頭で全部の信号を 0 にしているのは、書き忘れた信号を 0 にする (= OR に入れない) ため。
        クロックは無いので、命令が変わると数ゲート遅延で全部の制御信号が変わります。

      
試してみよう
        
    
          
  • プリセットの addi (0xfff50513) を押す。is_op_imm が 1 になり、reg_we と b_sel が 1、mem_* は 0。hw/README の波形の行と同じです。
    • 
          
  • lw → mem_read と wb_sel=MEM、sw → mem_write だけで reg_we=0。
    • 
          
  • beq と jal で a_sel=PC になる (飛び先 pc + imm を ALU で計算するため)。
    • 
          
  • opcode のビットを 1 つ手で変えて、どの行にも当たらず illegal が 1 になる opcode を探す。

6.ラッチ → フリップフロップ → レジスタ

  

    

      
D ラッチ (NAND 4 個 + NOT)

      

      
E = 1 の間は Q = D (素通し)、E = 0 にすると Q は直前の値を 覚え続けます。
        右の 2 つの NAND が互いの出力を入力に戻している (たすきがけ) のが記憶の正体です。

    

    

      
D フリップフロップ (マスタ・スレーブ)

      

        
        
        
        
      

      

      

      

      
D ラッチを 2 つつなぎ、前段 (マスタ) は CLK = 0 の間、後段 (スレーブ) は CLK = 1 の間だけ素通しにします。
        どの瞬間も片方は閉じているので、D が Q まで素通りすることはなく、CLK が 0 → 1 になる瞬間 (立ち上がりエッジ) の D だけが Q に入ります。
        Verilog の always @(posedge clk) q <= d; がこれです。

    

    

      
4 ビット レジスタ (書き込みイネーブル付き)

      

        
        
        
      

      

        

        

          

          
各ビットは D フリップフロップ 1 個。その前に 2:1 マルチプレクサを置き、we = 0 なら自分の出力 q を、
            we = 1 なら新しい値 d を D に入れます。だから we = 0 のときはクロックが来ても値が変わりません。

          
hw のレジスタファイルはこれを 64 ビット × 31 本 (x0 は常に 0) 並べたもので、書き込みはこの 2 行です:

          
27always @(posedge clk) begin28    if (we && rd != 5'd0)29        regs[rd] <= rd_val;

          
addi a0, a0, -1 では、ALU の出力 4 がこのサイクルのうちに rd_val まで届いて待っていて、
            次の立ち上がりエッジ で a0 が 5 → 4 に変わります (hw/README の波形で x_a0 が次の行で変わるのはこのため)。

          
→ regfile.v、
            「クロックの立ち上がりエッジで起きるのは 3 つだけ」

        

      

      
試してみよう
        
    
          
  • D フリップフロップで CLK = 1 のまま D を何度変えても Q は変わらない。CLK = 0 にしても変わらない。0 → 1 にした瞬間だけ Q が D になる。
    • 
          
  • 波形の縦の点線 (立ち上がりエッジ) の位置でだけ Q が変化していることを確かめる。
    • 
          
  • D ラッチで E = 1 のまま D を切り替えると Q がついてくる (素通し)。これがエッジで取り込むフリップフロップとの違い。
    • 
          
  • レジスタで we = 0 のままクロックを入れても q は変わらない。we = 1 にしてからクロックを入れると d が入る。
    • 
        

      

    

  







  
7.1 ビット ALU スライスを 4 つつなぐ

  

    

      

        
        
        
        
      

      

        

        

          

          

          
各スライスは 1 ビット分の AND・OR・全加算器を 全部同時に 計算しておき、最後に op で選んだ 1 つだけを
            4:1 マルチプレクサで出力します (使わない結果は捨てる)。SUB のときは B を XOR で反転し、最下位の桁上げ入力を 1 にして
            A + ~B + 1 = A − B を作ります (2 の補数)。alu.v の case (alu_op) も、合成すると
            「全部の演算器を並べて最後にマルチプレクサで選ぶ」形になります。

          
→ alu.v、
            defs.vh の ALU_*

        

      

      
試してみよう
        
    
          
  • op を AND → OR → ADD と変えて、同じ A, B から違う結果が選ばれるのを見る (AND / OR は桁上げを待たないので速く落ち着く)。
    • 
          
  • SUB で 5 − 6 を計算すると 1111 = −1。B の反転と、最下位の桁上げ 1 を確かめる。
    • 
          
  • ADD と SUB で安定までの時間を比べる。SUB は B の反転 (XOR) の分だけ長い。
    •
