試してみよう

        
    
          
  • C (cc/ の rvcc) または minilang (compiler/ の minicc) → RISC-V アセンブリ → asm/ の rvasm で機械語と ELF → emu/ のエミュレータで実行、を全部ブラウザの中でやっています。どのカラムの行もクリックすると、対応する行が他のカラムで光ります。
    • 
          
  • fib.c を -O0 と -O2 で「次の行」→「1 命令」と進めてみましょう。pc の位置が機械語・アセンブリ・C の行に同時に表示されます。-O0 では式の途中結果がスタックに積まれ、-O2 では s1 レジスタに置かれる (mv s1, a0) のが見えます。
    • 
          
  • printf の文字列を指す la a0, .Lstr0 は auipc + addi の 2 命令になり、R_RISCV_PCREL_HI20 / PCREL_LO12_I の 2 つのリロケーションで「pc からの距離」が埋め込まれます。リロケーション表の行をクリックして、ビット表示で即値の上位 20 ビットと下位 12 ビットを見比べてください。call も auipc + jalr です。
    • 
          
  • 下の「比較」で fib(25) を C (-O0 / -O2) と minilang で走らせると、動的型のコスト (タグ付き整数の検査・クロージャ経由の呼び出し) が実行命令数の差として出ます。minilang の fib 本体のアセンブリも開いて、C の 24 行と比べてみましょう。
