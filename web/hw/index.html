このページについて

        
    
          
  • hw/ の Verilog で書いた RISC-V CPU を、ビルド時に Icarus Verilog で本当にシミュレーションし、その波形 (VCD) を 1 クロックずつ再生しています。値はすべて回路の信号そのもので、ブラウザ側で命令を実行し直してはいません。
    • 
          
  • 単一サイクル版は「▶ 1 ステップ」を押すたびに ① 組み合わせ回路が落ち着く → ② クロックの立ち上がりエッジで pc・レジスタ・メモリが一斉に更新 の 2 段階で進みます。線の色はデコーダが出した制御信号で決めています (使われていない経路は薄い灰色)。
    • 
          
  • キーボード: → 進む、← 戻る、Space 再生/停止。命令のビットの欄にマウスを乗せると、そのビットが流れていく線が光ります。

      パイプラインは CPI > 1 なのに、なぜ速いのか
      
        
      パイプライン版の CPI (1 命令あたりのサイクル数) は 1 より大きくなります。分岐成立・ジャンプで 2 バブル、load-use で 1 バブル、ecall で 3 バブルが入るからです。
      
        
      それでも速いのは、1 サイクルの仕事が約 1/5 になるのでクロック周波数を上げられるからです。単一サイクル版のクロック周期は「命令 RAM → デコーダ → レジスタ → ALU → データ RAM → 書き戻し」の全部の遅延 (クリティカルパス) で決まります。パイプライン版は 1 ステージ分の遅延で済みます。
      
        
      シミュレータ上の「サイクル数」だけを見ると単一サイクル版が勝って見えるので注意。かかる時間 = サイクル数 × クロック周期 です。CPI を 1 に近づけるのが、分岐予測 (BTB)・分岐を ID で解決する・などの工夫です。(hw/README.md より)
