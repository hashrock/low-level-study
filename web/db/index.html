  1. ルートが分割される瞬間

    空のテーブルを作り、長い行を 1 行ずつ入れていきます。葉 (= 1 ページ) が 4096 バイトを超えると分割され、 ルートのページが内部ノードに変わり、元の中身は新しいページ (緑) に移ります。ルートのページ ID は変わらないのでカタログを書き換えずに済みます (ページ 0 で確認できます)。

  2. たくさん入れる

    users にランダムな主キーで 200 行。葉が増え、葉どうしが next (紫の矢印) でつながります。バーは使用バイト数。

  3. 主キー検索 vs 全件スキャン

    WHERE id = 5 はルートから葉まで 2 ページ (深さ分) だけ読みます。WHERE name = 'x' は全部の葉を next で辿り、全行をデコードします。 「ステートメント統計」の 読んだ行 と 触ったページ、木の青い点線 (読んだページ) を比べてください。

  4. キャッシュが小さいと

    キャッシュ容量を 4 ページにしてから全件スキャンすると、毎回ファイルから読み直し (ディスク読込)、古いページが追い出されます。

  5. 消しても縮まない

    DELETE は葉からキーを消すだけで、併合もページの再利用もしません。空きバイト (バーの残り) が増えるだけです。

  6. ファイルとして持ち出す

    右上の「.db を保存」でダウンロードしたファイルは CLI でそのまま開けます: cd db && go run . minidb.db。逆に CLI で作ったファイルも読み込めます。
